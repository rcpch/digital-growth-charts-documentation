# Security Policy

## Reporting A Vulnerability

Report suspected vulnerabilities privately to <growth.digital@rcpch.ac.uk>. Include the affected component, observed behaviour, reproduction details, and potential impact where it is safe to do so.

Do not disclose exploit details, credentials, security-sensitive configuration, or patient information in a public GitHub issue. Never include real patient data in a report. If a security issue could affect care, clinical calculations, patient data, or clinical workflow, the team will also assess it through the [clinical safety process](docs/safety/csmf/clinical-risk-mgmt-plan.md#security-incident-management-process).

General documentation defects that are not security-sensitive may be reported through the repository's [public issue tracker](https://github.com/rcpch/digital-growth-charts-documentation/issues).

## Scope

This policy covers the documentation source, generated site, and repository automation. Security reports concerning the API service or another Digital Growth Charts component can use the same private reporting address and should identify the affected repository or service.
